# 团建场地调研 Agent

一个把"调研 → 比价 → 发邮件"做完整的 Agent 实现。Python 3.12，**零第三方依赖**，直接跑：

```bash
cd team_building_agent
python run_demo.py                                  # 5 类边界场景，输出写到 demo_output.txt
python -m unittest discover -s tests -t .           # 23 条护栏单测
```

## 设计立场

这个任务的难点不是"会调工具"，而是**在信息不完整时不做假**。所以：

> **控制流交给代码，模型只负责"读文本"和"写引言"这两件无法规则化的事。**
> 模型的每一条输出都必须穿过一道代码写的闸门才能进入下一个环节。

让模型决定"下一步做什么"只会带来两种故障：跳步（没取证就比价）和绕圈（反复重搜）。
把流程写成有限状态机之后，这两类问题在结构上就不存在了。

## 需求 → 机制

| 需求 | 机制 | 代码位置 |
|---|---|---|
| 处理工具失败 | `ToolResult` 显式区分 `OK/EMPTY/FAILED/TIMEOUT`；工具异常在注册表边界被翻译成 `FAILED`，不炸穿主循环 | `tools.py` |
| 结果数量不定（0～N） | ① `EMPTY ≠ FAILED`：失败重试，空结果**换参数**（放宽条件分支）<br>② 每步只抓 2 个页面，处理不完就带缺口交付并标注 | `agent.py:_h_search / _h_fetch` |
| 6-8 步可控 | 确定性 Planner + 双预算：每版需求 8 步 / 全场硬上限 14 步；**工具重试不占步数** | `agent.py:_decide / AgentConfig` |
| 防止"假装比价" | 三层闸门（见下） | `extractors.py` / `reporting.py` / `verifier.py` |
| 中途改需求 | `Intent` 版本号 + 字段依赖标签；只作废"依赖被改字段"的产物 | `models.py:Intent` |

## 防幻觉的三层闸门

**第 1 层 · 取证层（最关键）**
`Evidence.value_span` 必须是来源正文的**连续子串**，否则直接丢弃并记账：

```
紫蓬山拓展基地：丢弃 1 条无法在原文逐字命中的片段（疑似编造）→ ['人均 288 元']
```

页面原文根本没提价格，抽取器"读"出来一个 288 —— 它格式合法、数字合理，
唯一的问题是不在原文里。这一层不信任模型的自律，只信字符串匹配。

**第 2 层 · 报告层（比价门槛）**

```
can_compare = 可核验报价 ≥ 2 条  且  来源 ≥ 2 个独立 URL
```

不满足就**不产出任何排序或推荐**，只列缺口：

```
未达到比价门槛 → 不产出任何排序或推荐：
  取得可核验报价的场地只有 1 个（构成比价需要 ≥2 个）；
  可核验报价只来自 1 个独立来源（需要 ≥2 个，避免同一个页面被当成多家比价）
```

未取证的场地一律显示"未取证"，绝不用估算值填空，也不参与排序。

**第 3 层 · 邮件层（数字溯源）**

表格由**代码渲染**，模型只能写引言。引言必须过 4 项检查：
① 不可比价时禁用"最便宜/最低价/性价比最高"等结论词；
② 每个报价数字必须能对上某条证据；
③ 同句内"场地名 + 价格"的配对必须与证据一致；
④ 声称"最优"必须指向报告里真正的最优项。

拦截后带批注回炉一次，仍不通过就**丢弃模型引言、改用代码模板**：

```
引言核对不通过 3 处，带批注回炉重写一次：正文出现无出处的报价数字 158（片段「158 元」不在任何证据中）
回炉后仍有 3 处不实 → 丢弃模型引言，改用代码模板引言
```

## 中途改需求的作废粒度

每个产物出生时带一枚指纹 `intent.digest(deps)`，只有指纹仍然匹配的产物才算有效。

| 改动 | 依赖标签 | 后果 |
|---|---|---|
| `city` 合肥 → 南京 | `location` | 候选与报价**全部作废**，重新检索 |
| `headcount` 40 → 60 | `scale` | **一条不废**，直接用旧证据重出报告 |
| `activity` 团建 → 年会 | `theme` | 报价作废（套餐价随活动变），场地保留 |

实测（S4）：改城市作废候选 6 个 + 证据 4 条；紧接着只改人数，作废 0 条。
如果套餐价按人数分档，把 `"scale"` 加进 `agent.py` 的 `PRICE_DEPS` 即可一行生效。

## 降级与"不做假"的兜底

| 情况 | 行为 |
|---|---|
| 检索彻底失败（含放宽重试） | `give_up`：**不产出报告、不发邮件**，只上报失败原因与工具调用统计 |
| 抓取失败 | 标 `fetch_failed`，报告标注"抓取失败，未取证"，不估算 |
| 步数预算耗尽 | `degraded`：按已有数据出报告，缺口如实标注 |
| 报价不足 2 条 | **必须人工确认**才能外发（低置信度结果不允许自动外发） |
| 邮件发送失败 | `send_failed`：落盘草稿到 `outbox/`，**绝不谎报送达** |

## 接真实依赖

三处替换，其余不用动：

```python
# 1) 联网检索/抓页面：换成 HTTP 客户端，保持返回 ToolResult
class SearchTool:  def __call__(self, city, keyword, wide, limit) -> ToolResult: ...

# 2) 发邮件：换成 SMTP / 邮件服务
class EmailTool:   def __call__(self, to, subject, body) -> ToolResult: ...

# 3) 抽取：换成 LLM，但必须返回原文子串 —— 校验层不变
extractor = LLMExtractor(llm_call=lambda prompt: call_your_llm(prompt))
```

`LLMExtractor` 的 prompt 里已经写明"span 必须原样复制，禁止改写/换算/补全"，
但**不要依赖这一点**：返回后统一过 `GroundingValidator`，这是唯一采信入口。

## 已知取舍

- **每一步抓 2 个页面**是预算换来的确定性：8 步内要留出比价+写信+发送。
  想覆盖更多场地就调 `AgentConfig.fetch_batch / max_fetch_steps`，代价是总步数上限要同步放宽。
- **引言被拦后降级为模板**而不是彻底不发：因为表格由代码渲染、天然可信，
  丢引言不影响事实正确性；真正会拦住"发出去"的是比价门槛和发送前二次核对。
- Mock 语料是写死的，不会触发真实的页面结构差异。换真实数据源时，
  `RuleExtractor` 大概率要换成 `LLMExtractor`，但下游三层闸门无需改动。
