## 切片权限过滤（基于元数据的角色控制）

需求：索引时给切片打元数据标签（如 `role: admin`），检索时按当前用户角色过滤，且标签后期可改。

关键设计决策：
- **权限标签不进 `text`**。一旦拼进 text（像标题路径那样），改权限就要重烧 embedding。改为外挂一份 `acl.json`，与 `index.faiss` / `chunks.pkl` 完全解耦 —— 改权限零重建。
- **权限粒度 ≥ 返回粒度**。parent_child 返回的是父块全文，所以判权必须按返回单元（标题路径 / parent_idx），不能按子块，否则 user 级子块会把含 admin 内容的父块全文带出去。
- **过滤位置：两路召回之后、`rrf_fuse` 之前**。晚了 BM25 无权限块会参与 RRF 打分，且 rerank 会把无权限正文 POST 给外部网关。
- **fail-closed**：`default` 用 `admin`（用户指定），文件缺失/角色名非法/标题失配一律判不可读。
- 匹配规则：rules 的 key 是标题路径，从深到浅逐级回退 = 最长前缀优先；配一级标题即覆盖整章。

改动文件：
- 新增 `rag/acl.py`：`load_acl` / `required_role` / `can_read` / `filter_by_role` / `write_template`；`ROLES=("user","admin")` 等级比较
- `rag/cli.py`：加 `--role`（默认 user），过滤插在两路召回之后，打印 `候选 N→M` 便于区分「权限挡住」和「真没召回」
- `rag/vector_store.py`：`build_index` 里调 `write_template(sections)`，**文件已存在则不覆盖**，防止重建冲掉手改的权限
- `rag/__init__.py`：分工表补 acl.py 一行
- 新增 `data/faiss/第一课.acl.json`：默认 admin，13 个一级标题骨架，其中「只有社会主义才能救中国」「综合探究一」手改为 user 作示例

已验证（用 3.13 解释器直接跑 acl 逻辑 + 真实 chunks.pkl）：user 可见 31/406，admin 406/406；子路径正确继承一级标题；无标题切片落 default；非法角色判不可读。未能端到端跑 `python -m rag.cli`（当前可用解释器都没有 faiss）。

数据卫生：源文件 `utils/clent_text/第一课.clean.md:141` 有一行 `# 2`，导致骨架里多出一个叫 `"2"` 的一级标题。
